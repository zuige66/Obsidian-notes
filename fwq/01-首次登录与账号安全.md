# 01：首次登录与账号安全

## 当前报错是什么意思

你已经成功连接到服务器，第一次出现的主机真实性提示是正常的。输入 `yes` 后，Windows 保存了服务器的 RSA 指纹。

`Permission denied, please try again.` 表示服务器拒绝了 root 的密码验证。网络、IP 和 SSH 端口本身是通的。

## 现在怎么做

如果仍停在第三次密码提示处，按 `Ctrl+C` 退出。不要反复猜密码，连续失败可能触发临时封禁。

1. 切到英文输入，检查大写锁定。
2. 注意大小写，以及数字 `0/1` 和字母 `O/l/I`。
3. 粘贴后不要输入多余空格。密码输入时不显示字符或星号是正常的。
4. 向提供服务器的人确认账号是否为 `root`、端口是否为 `22`、密码是否已改、是否只允许密钥登录。
5. 若你拥有云厂商后台权限，使用后台网页终端/VNC，或使用“重置密码”。操作前确认不会影响其他使用者。

不要把密码发到聊天、截图或 Markdown 中。恢复登录后应更换截图中暴露过的密码。

## 再次登录

在 Windows PowerShell 中：

```powershell
ssh root@104.168.22.222
```

如果实际端口不是 22：

```powershell
ssh -p 端口号 root@104.168.22.222
```

以后若突然出现 `REMOTE HOST IDENTIFICATION HAS CHANGED`，不要盲目删除记录，应先确认服务器是否重装或更换了密钥。

## 登录成功后先检查

```bash
whoami
hostname
cat /etc/os-release
uname -a
uptime
free -h
df -h
ip addr
ss -lntp
```

这些都是只读命令。退出用 `exit`。

## 更换已经暴露的密码

仅在服务器归你管理、且不会导致其他人失去访问权时执行：

```bash
passwd
```

使用至少 16 位的独立随机密码并存入密码管理器。长期建议使用普通用户和 SSH 密钥；必须先验证新方式能登录，再调整 root 或密码登录策略。
