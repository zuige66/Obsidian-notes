# 04：部署自己的服务

目标是不影响 80 端口上的现有网站。

```text
浏览器或小程序 → HTTPS 443 → Nginx → 127.0.0.1:3001（自己的程序）
```

自己的程序只监听 `127.0.0.1:3001`，Nginx 负责 HTTPS 和转发。部署前检查：

```bash
ss -lntp | grep ':3001'
nginx -T
```

如果 3001 已占用，就选择另一个端口。

## Nginx 结构示例

下面不能直接照抄，证书路径必须换成真实值：

```nginx
server {
    listen 443 ssl;
    server_name api.dentrobot.com;

    ssl_certificate /实际证书路径/fullchain.pem;
    ssl_certificate_key /实际证书路径/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

建议使用独立子域名 `api.dentrobot.com`，先在 DNS 中添加指向服务器 IP 的 A 记录。

## 安全修改顺序

1. 找到实际配置并备份。
2. 新增独立站点配置，不覆盖原站点。
3. 执行 `nginx -t`。
4. 检查成功后才执行 `systemctl reload nginx`。
5. 用 `curl -I` 和浏览器确认新旧服务都正常。

正式程序应由 `systemd` 管理，不要依赖一直开着的 SSH 窗口。具体配置取决于 Node.js、Python、Java 等技术。
